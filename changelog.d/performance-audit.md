### Changed

- **A performance pass over the server, the runner and Core.** An audit of the hot and warm paths removed redundant work without changing what any page, API or job returns.
  - The result view's 2 s status poll no longer resolves the nav bar's course context (three queries), because no JSON API handler reads it.
  - A runner poll with a backlog loads the claim candidates one group at a time and stops at the first claim, instead of reading all eight groups first. It reads each assignment's requirements once per poll. The queue-depth log field is one grouped count, and the job-assigned and result diagnostics reuse the rows their caller holds.
  - A decoded manifest is memoized by its exact bytes (`ManifestDecodeMemo`), so the many decodes of the same manifest in one request or poll cost one.
  - Test-script reads from a setup zip are cached per zip and validated by its size, time and central directory (`ZipScriptTextCache`). The notebook guide, the suite outline, the suite editor and MCP `get_suite` no longer start one `unzip` per script per request. Every read still goes through `unzip -p`, so a symlink entry returns its link text. The notebook cache remembers a setup with no notebook and caches each notebook's contribution slot count, so a passing result no longer starts `unzip` or parses the notebook.
  - A new index on `submissions(user_id, kind, submitted_at)` serves the result page's wardrobe grant and the per-user submission list, which scanned the whole table. Two more serve the course timeline and the BrightSpace health rule.
  - Polled and per-page reads select only the columns they use, count with SQL instead of loading rows, and read a user's group or latest submission with one row instead of the whole set. The student leaderboard poll builds only the rows it shows. The result page loads its setup, course, extension and class-goal snapshots once.
  - ISO 8601 and Waterloo date formatting use value-type format styles in place of a new formatter per call, and match the old output byte for byte. Hex digests, URL encoding, the poll ETag, the CSP header and the inlined SVG sprites cost less per request. Regexes are built once per scan, not once per line.
  - The runner encodes each result once, stages round-robin opponents up to eight at a time, runs recursive copies and deletes off the cooperative pool, deletes an evicted setup outside the cache actor, and detects submission file types with one `file` call per batch.
