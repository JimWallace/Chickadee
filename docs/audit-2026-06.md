# Codebase Audit — June 2026 (v0.4.412)

A whole-codebase audit covering the server route layer, the worker daemon and
grading core, database usage, and the frontend (JS + Leaf templates).  Each
finding cites file:line as of v0.4.412.  Findings are ranked by impact × ease
within each section; the cross-cutting priority list is at the top.

This is an *audit document*.  Each item is sized so it can become an issue/PR
on its own.

### Implementation status (second pass — "do it all" batch)

Implemented on top of the "now" batch:

- **P1.1 — grade denormalization.**  `AddResultGradeColumns` adds
  `earned_points` / `total_points` / `pass_count` / `total_tests` to `results`
  with a one-statement SQL backfill (dialect-specific: `jsonb->>'…'` on
  Postgres, `json_extract` on SQLite).  `APIResult`'s designated initializer
  stamps the columns (`populateGradeFields()`), covering the worker, browser,
  and bundle-import creation paths.  Column-first accessors
  (`gradePercentValue` / `gradePointsValue` / `gradeTotalPointsValue`) replace
  the per-row blob parses at all twelve read sites (dashboard, roster, CSV,
  history, achievement sweep, BrightSpace sweep); rows with all-nil columns
  fall back to the JSON parse so the two paths can never disagree.
- **P0.2 — bind-limit chunking.**  `preferredResultsBySubmissionID` chunks its
  `IN`-list at 5,000 IDs (each submission's results live entirely inside its
  ID's chunk, so the per-submission fold is order-equivalent).
- **P0.3 — attempt-number race.**  `saveSubmissionWithNextAttemptNumber`
  computes `MAX(attempt_number)+1` and saves inside one transaction, with a
  per-(setup, user) `pg_advisory_xact_lock` on Postgres (SQLite write
  transactions already serialize).  Rewired all five count-then-insert sites
  (web submit, two API paths, two browser paths); validation submissions keep
  the old behavior.
- **P1.3 — claim-scan cap.**  `collectClaimCandidates` queries fresh-then-retest
  groups separately with `LIMIT 50` each (preserving #427 priority in SQL,
  dropping the full scan + in-memory re-sort); validation scan capped too.
- **P1.8 — per-claim zip hashing memoized** (`TestSetupDownloadVersionCache`,
  keyed on manifest + zip path/size/mtime).
- **P1.2 — achievement sweep**: setups batch-loaded in one query instead of a
  find() per assignment; interval 60 s → 5 min.
- **P1.6 — dashboard aggregates**: pending-now is a SQL `COUNT`; per-setup
  unique submitters is `COUNT(DISTINCT user_id) … GROUP BY`.
- **P2.3 — result persist + status flip transactional** (`ResultRoutes`).
- **P2.4 — TestSetupCache** seeds its LRU from disk at init (restart no longer
  orphans entries) and copies to scratch outside actor isolation (one
  re-acquire retry covers an eviction racing the copy).
- **P2.5 — `JobPollerError.decodingFailed`** distinguishes schema mismatch from
  transport failure (`job_decode_failed` log status).
- **P1.5 — process-wait continuations.**  macOS: `terminationHandler` +
  single-shot continuation (with already-exited rescue); Linux fork path:
  `waitpid` loop on a dedicated thread + continuation.  The cooperative pool
  no longer loses a thread per running script, so heartbeats and the timeout
  task keep running.
- **P2.1 — output capture capped** at 1 MB per stream with a truncation marker.
- **Worker odds and ends:** artifact-download resource timeout 15 s → 10 min
  (was deterministically failing large zips); `scriptInvocation` bounded 2 KB
  read; `interpretScriptOutput` single stdout split; `makeCollection` single
  pass; `submissions(assigned_at)` index added.
- **Frontend:** `Public/relative-time.js` replaces the six drifted
  per-template `formatRelative` copies (all six templates rewired); the two
  50 ms `setInterval` spinners (pattern-family scan, suite-table form submit)
  replaced with cached/settled promises; `loadGradesCSVStudents` and
  `EnrollCSVHelper` filter in SQL instead of loading all users.

**Still open (refactor-only, no behavior change):** role/status string → enum
sweep, the generic periodic-service extraction, `loadAssignmentAndSetup` /
`AppError` adoption completion, the oversized-file splits,
`NotebookWorkingCopyStore` extraction (+ moving the legacy notebook sweep to a
startup migration), the multipart `ManyOrSingle<File>` dedup, the shared
`chickadee-ui.js` (escaper/csrf/setStatus) module, BrightSpace sweep
per-result query batching, and `GET /api/v1/submissions` pagination.  These
are mechanical consolidations whose value is maintainability rather than
correctness or scale; they should land as focused PRs.

### Implementation status (first pass — "now" batch)

The "now" batch has been implemented on this branch alongside the audit:

- **P0.1 — worker script env allowlist.**  `mergedScriptEnvironment`
  (`Sources/Worker/ScriptRunner.swift`) now starts from an allowlist
  (`PATH`/`HOME`/`LANG`/`LC_*`/`TMPDIR`/… + `CHICKADEE_*` overrides) instead of
  the full daemon environment, so `RUNNER_SHARED_SECRET` and other secrets are
  no longer inherited by student scripts.  Covers all four execution paths
  (sandboxed + unsandboxed, macOS + Linux) through the one function.
- **P1.4 — bulk retest UPDATE.**  `retestAllSubmissionsForSetup` /
  `retestStudentSubmissionsForSetup` now delegate to one
  `bulkFlipStudentSubmissionsToPending` that issues a single `UPDATE` (count +
  set) instead of a save per row; self-atomic, constant round-trips.
- **P1.7 — audit-followup indexes.**  New `CreateAuditFollowupIndexes`
  migration adds `request_metrics(finished_at)`, `submissions(submitted_at)`,
  `submissions(worker_id, status)`, `client_diagnostics(created_at)`, and
  `assignments(validation_submission_id)`.
- **P2.2 — `_ck_inputs.py` write now throws** instead of `try?`, so a failed
  write becomes an honest `buildStatus: failed` (retestable) rather than a
  confusing per-student traceback persisted as a grade.
- **Dead code removed:** the pre-v0.4.79 `resolveEditSuiteFiles` chain (~215
  lines + its tests) and the superseded Pyodide grading engine in `notebook.js`
  (~227 lines).
- **`suite-list.js`:** fixed the real production landmine (the create page
  loaded `suite-table.js` without `suite-list.js`, so a file upload threw) and
  the `upsertUploadItems` use-before-declaration bug.  Full module
  consolidation deferred — the functions are under test.

**Deferred (own PRs, higher risk / larger):** P1.1 grade denormalization (schema
migration + backfill + rewiring six read sites), the oversized-file splits, the
role/status enum migrations, the shared `chickadee-ui.js` / `relative-time.js`
frontend modules (the six `formatRelative` copies have drifted and the admin
templates aren't covered by runtime tests), and the worker process-wait
continuations (P1.5).  The micro-optimization to hoist the runner's
`ISO8601DateFormatter` is dropped: a shared global of a non-Sendable type trips
Swift 6's concurrency check and the codebase has no `nonisolated(unsafe)`
precedent.

## Priority list (cross-cutting, ordered)

**P0 — correctness / security at realistic term scale**

1. **Worker scripts inherit `RUNNER_SHARED_SECRET`.** Student test scripts
   run with the worker's full environment (`Sources/Worker/ScriptRunner.swift:223`
   `mergedScriptEnvironment` starts from `ProcessInfo.processInfo.environment`;
   the Linux fork path mirrors it via `setenv` at `:391-394`).  In the systemd
   deployment the worker env contains `RUNNER_SHARED_SECRET`
   (`deploy/chickadee-runner.service:15` + `deploy/.env.example:66`), so a
   submission can `print(os.environ["RUNNER_SHARED_SECRET"])`, read it back
   from its own `longResult`, and then HMAC-sign worker API requests (claim
   jobs, forge results for any submission).  The Linux `--net` sandbox doesn't
   help — stdout is the exfiltration channel — and `docker-compose.yml:107`
   doesn't pass `--sandbox` anyway.  This is the same leak class the v0.4.x
   tock audit fixed for `PersonalizationEvaluator`; the worker path was missed.
   *Fix:* allowlist base env (`PATH`, `HOME`, `LANG`, `LC_*`, `TMPDIR`) +
   explicit `CHICKADEE_*` overrides.  Small change, one function.

2. **Grades CSV export breaks at term scale.**
   `InstructorDashboardRoutes+Submissions.swift:164-181` loads every student
   submission for every setup, then `preferredResultsBySubmissionID`
   (`:809-836`) issues `.filter(\.$submissionID ~~ submissionIDs)` with the
   full ID list.  At ~200k submissions/term this exceeds bind-parameter limits
   (SQLite 32k, Postgres wire 65,535) — the endpoint errors outright — and
   below the limit it pulls every `collection_json` blob into memory to read
   one number each.  *Fix:* see P1.1 (grade denormalization) + chunk any
   unavoidable `~~` lists.

3. **Attempt-number race.**  Attempt numbers are computed count-then-insert
   with no transaction or unique constraint
   (`WebRoutes+Submission.swift:208-223`, `SubmissionRoutes.swift:42-55`).
   Concurrent submits get the same `attemptNumber`, silently corrupting the
   prior-attempt delta and First-Try-Perfect.  The API variant also counts
   per-*setup* rather than per-user — likely a second bug.  *Fix:* transaction
   with `MAX(attempt_number)+1` (or a unique `(user, setup, attempt)` index).

**P1 — efficiency fixes that remove most term-scale pain**

1. **Denormalize the grade out of `collection_json`.**  The grade exists only
   inside the full result JSON blob; `gradePercentFromCollectionJSON`
   (`AssignmentHelpers.swift:150-199`) parses the whole document to read two
   numbers.  Every list surface pays this per-row: student dashboard
   (`WebRoutes.swift:225-259`), instructor roster
   (`InstructorDashboardRoutes+Submissions.swift:255,348`), history pages,
   the achievement sweep, the BrightSpace sweep, the CSV export.  *Fix:* add
   `earned_points` / `total_points` (+ source-preference rank) columns on
   `results`, written at `ResultRoutes.persistToDB` time; backfill once.
   This single change converts six hot paths into column reads / SQL
   aggregates.  **Highest-leverage change in the codebase.**

2. **Achievement class-goal sweep is an unbounded N+1 every 60 s.**
   `AchievementEvaluationService.swift:45-68` loads all assignments, then
   per-assignment `APITestSetup.find` (full manifest) + enrolled count; for
   each class-goal assignment, `bestAssignmentGradeByStudent` (`:114-134`)
   loads every submission and result blob.  *Fix:* filter to
   class-goal-bearing assignments before fetching setups; use the P1.1 grade
   column; lengthen the interval.

3. **Worker claim path is O(all pending) inside a globally serialized
   transaction.**  `WorkerJobRoutes.swift:302-360` loads all pending
   submissions with no LIMIT, re-sorts in memory (making the DB sort at
   `:308` redundant), then runs 2 queries + diagnostics writes per candidate
   inside the claim transaction, all serialized by `WorkerClaimQueue`
   (`:113-127`).  After a 10k retest fan-out, claim throughput collapses
   exactly when the queue is deepest.  *Fix:* `LIMIT ~50` on the scan, cache
   `AssignmentRequirement` by assignment, move diagnostics outside the
   transaction.

4. **"Retest all" issues one UPDATE per submission on the request thread.**
   `RunnerValidationHelpers.swift:305-329` + `flipSubmissionToPending`
   (`:400-417`): 20k sequential saves, untransacted, blocking the
   instructor's Save (also triggered implicitly by manifest-change retests
   and MCP content edits).  *Fix:* one bulk
   `UPDATE … WHERE test_setup_id = ? AND kind = 'student'` via Fluent
   `.set(...).update()`.

5. **Script execution blocks Swift-concurrency pool threads.**
   macOS: `proc.waitUntilExit()` inside async (`ScriptRunner.swift:109`);
   Linux: `linuxWaitForChild` busy-polls `waitpid(WNOHANG)` + `usleep`
   (`:403-433`).  With `--max-jobs 4` on a 2-core container, running scripts
   pin the cooperative pool: heartbeats stall (server thinks the runner died)
   and on macOS the timeout task itself may never fire.  *Fix:*
   `Process.terminationHandler` + `withCheckedContinuation` — the pattern
   `Core/ZipArchiver.swift:140-170` already uses.  Related: `runMake` does a
   synchronous `waitUntilExit` **inside the `WorkerDaemon` actor**
   (`RunnerDaemon.swift:573-583`), serializing all job prep and heartbeats
   behind a long `make`; make the per-job pipeline `nonisolated` and confine
   the actor to the two shared fields.

6. **Instructor dashboard loads all course submissions (twice) to compute
   counts.**  `InstructorDashboardRoutes+List.swift:280-286` (full rows just
   to count pending), `:405-415` (full rows again for distinct submitters,
   plus a ~2,000-UUID IN-clause).  *Fix:* `COUNT(*)` / `COUNT(DISTINCT
   user_id) … GROUP BY` — the codebase already does this correctly at
   `AdminRoutes+Runners.swift:252-260`.

7. **Missing indexes** (verified against actual query predicates):
   - `request_metrics(finished_at)` — table has **no indexes at all** yet
     grows by ~30k rows/day/runner and is filtered on `finished_at` by both
     the time-series query and the prune.
   - `submissions(submitted_at)` and `submissions(assigned_at)` — the queue-depth
     and 24h-window queries can't use the existing `(status, kind, submitted_at)`.
   - `submissions(worker_id, status)` — admin runner GROUP BY, polled every 5 s.
   - `client_diagnostics(created_at)`; `assignments(validation_submission_id)`.

8. **Per-job test-setup zip hashing.**  `testSetupDownloadVersion`
   (`WorkerJobRoutes.swift:484-491`) reads and SHA-256s the whole setup zip
   on every claim.  *Fix:* persist the hash on the `test_setups` row at
   upload/save time (the manifest hash for the v0.4.93 retest gate already
   lives there) or memoize by `(path, mtime, size)`.

**P2 — robustness**

1. **Unbounded script output capture.**  `CapturedPipeBuffer`
   (`ScriptRunner.swift:45-56`) appends without cap; a print-loop submission
   can OOM the worker (killing the other concurrent jobs) and the blob rides
   `longResult` into the DB.  *Fix:* cap per stream (~1 MB) + truncation marker.
2. **`_ck_inputs.py` write failure swallowed.**
   `RunnerDaemon+JobProcessing.swift:573-575` uses `try?`; on failure every
   personalized test errors with a traceback that looks like a student
   mistake and is persisted as their grade.  *Fix:* `try` — the thrown error
   routes to `buildStatus: failed`, which is honest and retestable.
3. **Result persist + status flip not atomic** (`ResultRoutes.swift:39-43`);
   a failure between leaves duplicate work for the reaper.  Free transaction.
4. **`TestSetupCache` never reconciles with disk** (`TestSetupCache.swift:25-28`):
   LRU state is memory-only, so restarts + manifest edits orphan prepared
   directories in `/tmp/chickadee-runner-cache` forever.  *Fix:* seed
   `lruKeys` from a directory scan at init.  Also move the synchronous
   `copyToScratch` full-tree copy off-actor.
5. **Job decode failure misclassified as `transportError`**
   (`JobPoller.swift:77`) → schema mismatch retries forever under a
   misleading log status.  Add a `decodingFailed` case.
6. **BrightSpace sweep is 5 queries per pending result**
   (`BrightSpaceGradeSyncService.swift:57-117`); after a mass retest that's
   tens of thousands of queries per 60 s sweep.  Batch lookups, dedupe by
   (user, setup).
7. **Unbounded `.all()` endpoints:** `GET /api/v1/submissions` with no filter
   returns the entire table (`SubmissionQueryRoutes.swift:25-42`);
   `maxQueueDepthSince` does three full-model window scans per admin metrics
   request (`OperationalDiagnostics+Queries.swift:111-139`).  Add limits /
   SQL aggregates.

## Maintainability: the dominant pattern is *unfinished adoption*

The right abstractions almost always exist — they were each rolled out to
only part of the surface.  Finishing the rollout is cheap and high-yield:

1. **`loadAssignmentAndSetup(_:)`** (`SuiteEditHelpers.swift:39-46`) is used
   at 12 of ~37 sites; ~25 handlers still inline the
   publicID-parse + lookup + guard + 404 chain
   (`PublishedAssignmentRoutes+*`, `InstructorDashboardRoutes*`).  Finishing
   adoption also gives one place to enforce the instructor-enrollment policy
   (`CourseAccessHelpers.swift:8-13`), which is currently applied on
   student-facing routes but **not** on e.g. `assignmentSubmissionsPage`
   (`InstructorDashboardRoutes+Submissions.swift:236-240`) — verify whether
   that asymmetry is intentional.
2. **`preferredResultsBySubmissionID`** is implemented three more times
   inline (`WebRoutes+Submission.swift:289-308`, `:482-492`, `:514-518`).
   Call the shared helper; move it from the instructor route file to
   `Helpers/`.
3. **`AppError` vs `WebAssignmentError`** duplicate six of eight cases
   verbatim (`Errors/APIErrors.swift:96-224`), while 48 bare `Abort(...)`
   sites survive across 17 files; `WebRoutes+Notebook.swift` mixes all three
   vocabularies.  Fold the two extra cases into `AppError`, typealias during
   migration.
4. **`submissionPage` fetches the same `APITestSetup` five times and decodes
   its manifest four times per request**
   (`WebRoutes+Submission.swift:352-475` plus helpers in `ClassGoalBonus`,
   `AchievementBadgeEvaluation`).  Fetch once, decode once, pass
   `(setup, props)` to the helpers.  Hottest student-facing page; mechanical.
5. **Stringly-typed `role` and `status`.**  `APIUser.role: String` compared
   as literals at 47 sites; `APISubmission.status` literals at ~24 sites.
   `APISubmission.Kind` proves the pattern; raw-value enums need no
   migration.  Same for the `"support"` pseudo-tier and `"worker"|"browser"`
   grading-mode strings (the typed `TestProperties.gradingMode` enum already
   exists).
6. **Eight hand-rolled periodic services.**  `SessionReaper`,
   `StuckSubmissionReaper`, `MCPOAuthReaper`, `AuditLogReaper`,
   `AssignmentDeadline`, `BrightSpaceGradeSync`, `AchievementEvaluation`,
   `ServerHealthAlert` each repeat the same ~85-line Monitor + StorageKey +
   LifecycleHandler + `while !Task.isCancelled` scaffolding.  Extract one
   generic `PeriodicService(name:interval:sweep:)`; each service file
   shrinks to its sweep function.

## Smaller items (grab-bag, all verified)

- `ISO8601DateFormatter()` allocated per row / per log line:
  `RunnerDaemon.swift:84` (structured-log hot path — hoist to `static let`),
  `AdminRoutes.swift:90`, `AdminRoutes+Courses.swift:420`,
  `AdminRoutes+MCP.swift:152`.
- `mergeFiles` six-pass `makeCollection` (`+JobProcessing.swift:612-621`,
  4×`.filter{}.count` + 2×`reduce`) — the codebase's own stated antipattern.
- `downloadSession.timeoutIntervalForResource = 15` (`RunnerDaemon.swift:273`)
  hard-caps artifact downloads at 15 s — a large zip on a slow link can
  *never* download and retries can't fix it.
- `interpretScriptOutput` splits stdout twice
  (`RunnerCore/OutputInterpretation.swift:53,82`).
- Two `JSONValue` types with the same name (`RunnerCore/JSONLite.swift:5`
  internal vs `Core/JSONValue.swift:12` public) — rename the JSONLite one
  before someone makes it public for the wasm bridge.

  (`ScriptInvocation.swift:63-67`); its `pythonBootstrap` near-duplicates
  `sitecustomizePy` builtins logic without drift-test protection.

  in memory (`VanityURLRoutes.swift:56-87`) despite the unique
  `(course_id, slug)` index.
- `loadGradesCSVStudents` fetches all students system-wide then filters in
  memory (`InstructorDashboardRoutes+Submissions.swift:109-113`); same for
  `EnrollCSVHelper.swift:185`.
- Synchronous file I/O on the event loop in notebook/submission paths
  (`WebRoutes+Notebook.swift:496,685,746`, `WebRoutes+Submission.swift:204`)
  — use `req.fileio` or a blocking-IO pool.
- Backgrounded admin tabs poll forever: `admin.leaf:604,608` and

- JS-set inline status colors (`test-editor-modal.js:211`,
  `achievements-editor.js:89-91`, …) bypass the no-inline-styles convention
  because `check-styles.sh` only scans templates; the shared `setStatus`

- 50 ms `setInterval` spinners instead of cached in-flight promises
  (`pattern-family-editor.js:301-306`, `suite-table.js:1296-1303`).
- Multipart body structs duplicated ×4 for the array-vs-single `File` Safari
  quirk (`DraftAssignmentRoutes+NewAssignment.swift:372-404`,
  `+SaveValidation.swift:82-105`) — one `ManyOrSingle<File>` wrapper.
- Stale comments: `ScriptRunner.swift:3-5` ("Phase 4 will add
  SandboxedScriptRunner" — shipped long ago);
  `StudentCourseRoutes+History.swift:12-15` (claims a file name that's
  already been renamed).
