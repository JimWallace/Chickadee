# Codebase Audit — September 2026 (v0.5.290)

A "keep it simple, keep it idiomatic" pass over the last month of work
(v0.5.180 → v0.5.290, 2026-08-30 → 2026-09-30). The window added LTI 1.3,
GitHub submissions, class activities, course terms with the new-term clone,
the admin and instructor page redesigns, avatars and class handles, and the
Swift 6.4 toolchain move with swift-subprocess.

This document is the companion to `docs/audit-2026-07.md`. Every item in that
audit (#1103 to #1129) is closed. Nothing here re-files one of them.

## Status and method

Read this section first. It says what was measured and what was not.

| Step | Done | How |
|---|---|---|
| Structural scan of the whole tree | yes | sizes, churn, smell counts, lint baseline, by hand |
| Deep sweep: LTI 1.3 | yes | one auditing agent; the three top findings re-checked by hand against the tree |
| Deep sweeps: 15 other areas | **no** | defined (see "The audit programme") and not run: the session hit its usage limit |
| Adversarial verification of findings | **partial** | the LTI findings marked *verified* below were checked by hand; the rest carry the sweep's own confidence |

So the priority list below has two kinds of entries. An entry marked
**verified** cites lines that were read in the current tree. An entry marked
**candidate** comes from the structural scan or from commit history, and the
first step of its PR is to confirm it.

## Priority list

Each item is one pull request. Effort: S under two hours, M half a day to a
day, L more than a day.

### P1 — correctness and operations

1. **LTI login-state and deep-link rows are never reaped. Verified.**
   `LTIRoutes+Launch.swift:98` writes an `APILTILoginState` row on every
   unauthenticated `/lti/login` hit. `APILTIDeepLinkRequest` rows are written
   per picker open. No reaper or retention service names either model
   (`grep -rn APILTILoginState Sources/APIServer/Services` is empty). A
   crawler or a misconfigured LMS grows two tables without bound.
   *Proposal:* add both models to `MCPOAuthReaperService`, which already
   drops dead single-use OAuth rows hourly, and rename it to say what it
   reaps. Add one test per model. **S.**

2. **Deleting an LTI platform strands its bound courses. Verified.**
   `AdminRoutes+LTI.swift:117-125` calls `platform.delete(on:)` and redirects.
   `courses.lti_platform_id` (`APICourse.swift:103`) is a bare UUID column
   with no foreign key (`AddLTILaunchColumns.swift:16`). A bound course keeps
   a dangling platform ID: AGS grade pushes find no platform, and the course
   cannot be re-bound because `ltiGradesEnabled && ltiPlatformID != nil`
   still reads as bound.
   *Proposal:* refuse the delete while any course is bound and show the
   count, which matches how archival is gated elsewhere. Add a test. **S.**

3. **A restore to a fresh host loses the LTI tool key.** From the LTI sweep.
   `scripts/snapshot.sh` and `scripts/restore.sh` predate the per-integration
   key files (`LTIToolKeyProvider`, the MCP ES256 key, the GitHub App
   secrets). After a restore every LTI launch fails signature verification at
   the LMS until an admin re-registers the platform. Confirm the file list
   the snapshot copies, then add the key files. **S.**

### P2 — structure and duplication

4. **Two private-key-file loaders are copies, and both leave a
   write-then-chmod window. Verified.**
   `LTIToolKeyAuthority.loadOrGenerate` (`LTIToolKeyAuthority.swift:42-50`)
   and `MCPTokenAuthority.loadOrGenerate` (`MCPTokenAuthority.swift:47-56`)
   write the PEM and then call `setAttributes([.posixPermissions: 0o600])`.
   `GitHubAppSecrets.swift:33` already does it correctly in one call with
   `createFile(atPath:contents:attributes:)`.
   *Proposal:* one `PrivateKeyFile.loadOrCreate(path:generate:)` helper used by
   all three. Delete the two copies. **S.**

5. **`burnConsumable` is a generic primitive that lives on an MCP route
   extension.** From the LTI sweep. The atomic
   `UPDATE … WHERE consumed = false RETURNING` single-use primitive in
   `MCPOAuthRoutes+Token.swift` now has two LTI callers
   (`LTIRoutes+Launch.swift`, `LTIDeepLinkRoutes.swift`). Move it to
   `Helpers/` under its own name and update the doc comment. **S.**

6. **The AGS sweep classifies failures by `BrightSpaceSyncError`.** From the
   LTI sweep. `bestGradeForStudent` (`BrightSpaceGradeSelection.swift`) throws
   a transport-named error, so `LTIGradeSyncSweep` must import the Valence
   error taxonomy to decide what is transient, and the transient-status list
   is copied. Give grade selection its own small error type and let each
   transport map it. **S.**

7. **AGS retry-on-launch keys on the stored human sentence.** From the LTI
   sweep. `LTIGradeSyncQueue` and `LTIGradeSyncSweep` compare
   `APILTIGradeSync.error` text to decide whether a launch should retry. A
   reworded message is a behaviour change. Store a machine-readable reason
   code next to the sentence. **S.**

8. **Three copy paths, three bugs this month. Candidate.** The commits
   "give copied assignments their shared support files" (2026-09-25),
   "carry the reference solution when a course or assignment is copied"
   (2026-09-22) and the new `CourseCloneService` (2026-09-29) show that the
   course clone, the course-bundle import and the MCP `clone_assignment`
   tool each copy an assignment with their own list of parts. Each missed a
   part. *Proposal:* one `AssignmentCopier` that owns the list of parts
   (manifest, zip, notebook, solution, support files, datasets, versions)
   and that all three call. The PR starts by diffing the three lists. **M.**

9. **`InstructorDashboardRoutes` is 21 files, and `+BrightSpace` is 1,111
   lines. Candidate.** The July audit split `BrightSpaceGradeSyncService`
   (#1116). The growth moved to the route extension, which is now the
   largest file in the tree. `AdminRoutes` has 8 extensions and
   `PublishedAssignmentRoutes` 10. *Proposal:* a route-layer sweep (see the
   programme) that first lists the ten longest handler closures, then moves
   the BrightSpace page logic behind a service facade. Do not regroup the
   extension files until the sweep says which grouping needs the fewest
   moves. **L, in slices.**

10. **The manifest has two representations that are kept in sync by hand.
    Candidate.** `TestProperties` is Codable (741 lines). The server edits
    manifests through `[String: Any]` dictionaries: `ManifestFieldEdits.swift`
    makes 11 `JSONSerialization` calls, and `makeWorkerManifestJSON` rebuilds
    a fresh dictionary, which CLAUDE.md records as the trap that turned a
    deliberate "None" language into "nobody has been asked". The mid-month
    fold added `makeWorkerManifestJSON(preserving:)` to carry fields through;
    that is a fix for the symptom. *Proposal:* a Core sweep that decides
    whether every edit site can round-trip through `TestProperties` instead,
    with `ManifestCodec` as the one encoder. If yes, the dictionary path and
    its "fresh dict" rule go away. **M to decide, L to do.**

11. **Three `NSLock` + `@unchecked Sendable` classes. Candidate.**
    `AssignmentVersionCaptureMiddleware.swift:32`, `AdminEventSink.swift:30`,
    `MCPVersionCapture.swift:38`. Each is a small mutable box. An `actor` fits
    where every caller already awaits. `Synchronization.Mutex` (Swift 6, on
    the Linux toolchain) fits where a synchronous lock is needed inside a
    middleware. One PR per class. **S each.**

12. **The three target READMEs describe the MVP, not the system. Verified.**
    `Sources/APIServer/README.md` says "No authentication — all submissions
    are anonymous for MVP" and lists a `student` tier. `Sources/Core/README.md`
    lists a five-field `TestProperties` and a `student` tier that `TestTier`
    does not have. `Sources/Worker/README.md` is closer but omits the
    capability profile, the setup cache and the activity staging. Every
    agent and new reader that opens a target directory reads these first.
    *Proposal:* replace each with ten lines that say what the target is for
    and point at CLAUDE.md and `docs/architecture.md`. Keep the Package.swift
    `exclude:` entries. **S.**

### P3 — hygiene

13. **`@unchecked Sendable` on ~40 Fluent models has no justifying comment.**
    CLAUDE.md requires one. The July audit measured 36 sites, all commented.
    The month's new models (LTI, GitHub, activities, handles) carry none.

    `docs/ui-ratchet-handoff.md` are closure records. Move all three to

17. **Small LTI items.** From the LTI sweep, each below one PR on its own;

## By subsystem

### LTI 1.3

The sweep read all 32 files, the models, the migrations, the templates and
all 19 test files. The shape is good and should be the pattern for the next
integration:

- `LTILaunchValidator` is a pure function with typed throws
  (`throws(LTILaunchError)`), one enum case per claim rule, and a negative
  test per rule. `LTIPlatformForm.validated()` has the same shape.
- Every launch refusal is one `AbortError` enum that carries the status, the
  user sentence and a log line that names the rule without echoing the token.
  The routes catch and log at the boundary.
- Single-use state and deep-link tickets are burned with the atomic
  conditional UPDATE before anything is read. The state is bound to the
  browser by a path-scoped partitioned cookie. The nonce is bound to the
  state row. `azp` is required when `aud` has several values. The platform
  key set is refetched once per 30 s on a verify failure.
- The dependency seams are closures on actors (`LTIServiceClient(send:)`,
  `LTIPlatformKeyCache(fetch:)`), so the flow tests drive the real route
  table against a stand-in LMS that signs with its own key.
- The AGS queue is one `(student, test setup)` row with no stored grade, so a
  queued push can never send a stale value. It is simpler than the Valence
  side. Both call `bestGradeForStudent`, so override, best-of and class-goal
  bonus mean one thing.

The defects are at the edges: retention (item 1), platform lifecycle
(item 2), backup (item 3), and three small taxonomy points (items 4 to 7).

- **Routes.** 131 files and 36k lines. The extension-per-feature split has

  view models (`WebContextTypes` 777 lines, `AdminContextTypes` 702).

- **Tooling.** 20 guard scripts with their own baselines, 28 workflows,
  68 top-level docs, and a CLAUDE.md near 1,000 lines.

  ESLint 10 and twenty structural guards all pass on `main`, and
  `check-guards.sh` proves each guard can fail.
- **Typed throws at the validation boundary.** The LTI validators show the
  shape every new validator should take.

  in July.
- **The mid-month fold worked.** `d4b0ad35` removed 1,596 lines of copies

## The audit programme

These are the sweeps that were defined and not run. Each is one agent
session of reading, and each returns at most twelve PR-sized findings plus a
list of what is healthy. Run them in this order; each later sweep is cheaper
once the earlier ones have landed.

| # | Sweep | Scope | The question it answers |
|---|---|---|---|
| 1 | Routes | `Sources/APIServer/Routes/**`, `Middleware/` | What may a route file contain? Which of the ten longest handlers break it? Which context structs are built twice? |
| 2 | Core and manifest | `Sources/Core`, `Sources/RunnerCore`, `ManifestFieldEdits` | Can the `[String: Any]` manifest path go? What in Core is server-only? |
| 3 | Taxonomy | `Services/`, `Helpers/`, `Utilities/` | The placement rule, the files that break it, the sweep and reaper shapes. |
| 4 | Copy paths | `CourseCloneService`, bundle import, `clone_assignment` | One list of assignment parts (item 8). |
| 5 | Activities | `ClassActivity`, the helpers, `WebRoutes+Leaderboard` | Are the two hidden axes still the model, or has per-kind code crept in? |
| 6 | GitHub | `Sources/APIServer/GitHub`, the routes, the webhook | One HTTP client? Privacy table enforced by the models? |
| 7 | Terms | `AcademicTerm`, the two resolvers | Does anything bypass `findActiveCourse` or `resolveMCPCourse`? |
| 8 | Identity | avatars, handles, wardrobe | Is a cosmetic feature carrying more machinery than it needs? |
| 9 | Worker | `Sources/Worker`, the seven personalization drivers | One spawn helper? One driver shape? What splits out of the 1,037-line job file? |
| 10 | Data | `Models/`, `Migrations/`, `DatabaseConfiguration` | Model naming, indexes for the new tables, when to fold migrations. |
| 11 | Idiom | all of `Sources/` | Lock classes, unstructured tasks, sleep loops, dictionary JSON, string errors. |
| 12 | MCP | `Sources/APIServer/MCP/**` | The per-tool boilerplate, the prose modules, the admin split. |
| 13 | Tests | `Tests/**` | Fixture builders, the helper split, suites that spin up an app for a pure function. |
| 14 | JS | `Public/*.js` | The kernel shim contract, the next core/wiring splits. |
| 15 | UI | `Resources/Views`, `styles.css`, the ratchets | Old idioms left beside the redesign partials; how each guard edit this month moved. |
| 16 | Tooling | `scripts/`, workflows, docs, CLAUDE.md | Guard overlap, workflow setup duplication, superseded docs, a shorter CLAUDE.md. |

Verification rule for every sweep: a finding is kept only when a second
reader opens the cited lines, checks CLAUDE.md and the linked doc for a
decision that settles it, and says the change makes the code smaller.
